keepass-yaml-env 🔐

Secure, local secret management for developers.
Load KeePass secrets directly into your development environment at runtime—no plain-text .env files required.

keepass-yaml-env is a CLI wrapper that bridges your KeePass (.kdbx) database and your application. It securely unlocks your database, extracts the secrets you specify in a YAML configuration file, and injects them directly into your program's environment variables in-memory.

When your program closes, the secrets vanish. They are never written to your hard drive.

✨ Features

  • Zero Plain-Text Secrets: Completely replaces local .env files.
  • Language Agnostic: Works with Python, Node.js, Go, Rust, or any CLI tool.
  • In-Memory Injection: Secrets are passed to the child process and destroyed upon exit.
  • Path-Based Resolution: Prevent collisions by fetching secrets via exact KeePass folder paths.
  • CI/CD Ready: Easy to integrate into automated testing pipelines.

📦 Installation

The recommended way to install keepass-yaml-env globally is using pipx. This installs the tool in an isolated environment but makes the command available everywhere on your system.

pipx install keepass-yaml-env

(Alternatively, you can use uv tool install keepass-yaml-env or standard pip install keepass-yaml-env depending on your workflow).

🚀 Quick Start (Simple Example)

Let's say you have a Python script (app.py) that needs a database password, but you don't want to hardcode it or put it in a .env file.

1. Set up your KeePassXC Database

  1. Open KeePassXC and create a database saved at ~/Documents/my_vault.kdbx.
  2. Inside the database, create an entry with the title local_postgres.
  3. Set the Username to admin and the Password to supersecret.

2. Create your mapping file (secrets.yaml)

Create a file named secrets.yaml in your project folder. This tells the tool where to find the database and which secrets map to which environment variables.

keepass_db: "~/Documents/my_vault.kdbx"

secrets:
  - entry_path: "local_postgres"
    attribute: "Username"
    env_var: "DB_USER"
    
  - entry_path: "local_postgres"
    attribute: "Password"
    env_var: "DB_PASSWORD"

3. Run your application

Instead of running python app.py, wrap your command with keepass-yaml-env:

keepass-yaml-env -f secrets.yaml -- python app.py

What happens next?

  1. You will be prompted securely in the terminal for your KeePass Master Password.
  2. The tool unlocks the database and finds the local_postgres entry.
  3. It spawns python app.py with DB_USER and DB_PASSWORD injected into the environment.

⚙️ Configuration Reference

The secrets.yaml file supports the following structure:

Root Level

Key Type Description
keepass_db string (Required) The file path to your .kdbx database. Supports ~ for home directory expansion.
secrets list (Required) A list of secret mapping objects.

Secret Mapping Object

Key Type Description
entry_path string (Required) The path to the entry in KeePass. For nested entries, use slashes (e.g., Root/Development/DB_Credentials).
attribute string (Required) The field to extract. Valid options: Password, Username, URL, Notes.
env_var string (Required) The exact name of the environment variable that will be injected into your application.

💡 Usage Examples

Because keepass-yaml-env acts as a POSIX-compliant wrapper, you can use it to run literally any terminal command.

Run a Node.js server:

keepass-yaml-env -f dev-secrets.yaml -- npm run start

Run a Docker container with local secrets:

keepass-yaml-env -f secrets.yaml -- docker compose up

Just print the secrets to the terminal (for debugging):

keepass-yaml-env -f secrets.yaml -- env | grep DB_

(Note: The -- double-dash is highly recommended. It explicitly tells the wrapper to stop parsing arguments so it doesn't accidentally consume flags meant for your application).
